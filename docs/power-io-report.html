每套工艺均有 20 个信号 I/O 和 2 个供电端口，全部具有固定物理矩形。8 行主电源轨的原生 pin 矩形连续，邻行共享边界极性一致。供电系统含水平轨、分别属于 VDD/VSS 的两条垂直主干及固定 VIA，导出的带电源 Verilog 与 OpenDB 完整端点分区一致。

哪些错误被验证器检出
  • 相邻行电源极性错误。
  • 删去 filler 后，原生单元电源轨形成缺口。
  • 切断垂直主干，供电网络分裂。
  • 引入 VDD/VSS 金属短接。
  • 把 I/O 从芯片边界移入内部。

验证器从独立的 OpenDB 矩形、实际 VIA 和 N/FS 坐标出发，使用有上限的几何连通检查；没有把 RustROAD 自己的通过标记当作 oracle。

逻辑和时序仍有独立校验

原生与 Yosys CEC、每套工艺 512 组仿真向量均通过。tie 高低输出由真实 Liberty 的函数和反向错误控制确认。普通 Verilog 导出保留逻辑接口，供电版导出保留 filler、PG 端口和引脚。

  • sky130：最大 setup/hold 偏差 6.029404e-07 ns；14 个约束端点，2 个常量驱动 D 引脚缺少数据到达路径，已明确列出。
  • gf180：最大 setup/hold 偏差 8.695038e-07 ns；14 个约束端点，2 个常量驱动 D 引脚缺少数据到达路径，已明确列出。

时序采用理想线网、理想时钟，容差 0.001 ns；常量端点的覆盖限制没有被改写为零。增量检查为无修改更新，尚不代表完成实际 ECO 或寄生参数时序验证。

实现、资源和收据

所有权威几何为 i64 DBU。I/O、常量展开、filler、轨道区间和生成线段都有硬上限。版本 3 快照在原有连接表之外增加 physical.rbin；重新打开时重建并核对物理状态。写入仍由锁与 --base-rev 保护。

完整双 PDK 验证耗时 0:06.90，最大宿主进程 RSS 为 290,696 KiB。这包括导入、放置、导出、仿真构建、独立检查和时序分析；是小设计功能基线，不是工业级吞吐量或功耗结论。
