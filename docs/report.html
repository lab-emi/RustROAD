性能观察与资源上限

AMD Ryzen 9 9950X3D，Linux x86_64。50,000 单元 / 2,500 行，完整导入、放置、快照发布、mmap 读取、DEF 导出及独立检查：1 线程 0.373 秒，2 线程 0.373 秒。外层最大进程 RSS 62,592 KiB。每种配置仅一次观察，不构成统计加速结论，也没有与 OpenROAD 比速。

逻辑子流程整体 10.09 秒，最大进程 RSS 290,124 KiB。各子进程限制 2 GiB 地址空间、30 秒、有限输出，顺序运行。最大进程 RSS 不等于整个进程组同步合计峰值。

布局默认上限：250,000 单元、100,000 行、350,000 次候选扩展、16 MiB 输入/元数据。内核没有全路径枚举；布局工作量 O(单元 + 行)。

固定身份与可复现性

OpenROAD 的实际版本输出是 unknown，因此用 OCI 镜像内容 ID 和可执行文件 SHA-256 固定身份。REA 直接记录的是 podman 包装进程，需要另外保留目标二进制的哈希。部分 /proc 读取出现 EACCES，观察盲区没有被隐藏。

先选可测量的渲染边界

建议以 egui / eframe + 专用 wgpu 画布开始，保留 GPUI 为实测候选。

决定大电路视图性能的主要因素是可见区域筛选、LOD、常驻缓冲区与批量绘制，不能为每个单元或线段创建一个 UI 控件。wgpu 覆盖 macOS Metal 与 Linux Vulkan；egui-wgpu 提供明确的自定义渲染回调。GPUI 的公开文档支持 macOS / Linux，但仍处于 pre-1.0，必须先验证真实电路的批处理接入和版本稳定性。

权威坐标始终是 i64 DBU；仅在减去相机/分块原点后生成局部 GPU 浮点坐标。分层空间索引、查询输出、网格化、缓存、标签和同时驻留快照都有硬上限。GPU 计算另遵循 CPU 参考 → CUDA / Metal / Accelerate 的验证顺序。

尚未在 Mac 上运行，也没有 GUI 性能排行榜。 候选对比 · 实际 Mac / Linux 验收计划

公开依据：egui-wgpu 回调 · wgpu 平台 · GPUI 0.2.2 文档

下一阶段的完成条件

  1. 真实 LEF 与映射网表连接导入，双 PDK 单位、site、master、pin 一致性检查。
  2. 有界、网感知的布局优化及合法化；用独立 oracle 衡量线长、密度与时序。
  3. CTS、布线、SPEF 提取，RustSTA 改动后的增量/完整一致性与 OpenSTA 对照。
  4. 真实单元 GDS 流出与独立 DRC / LVS，再连接 RTL / 门级仿真及形式等价。
  5. 在真实 Mac 和 Linux 上比较候选画布的 p95 交互延迟、显存和端到端加载时间。

本次保留了 RustSys / RustSTA 的既有版本与冻结二进制。RustSTA 工作目录另有未提交的 SPEF 开发，未将其作为本次已验证能力。

启动首个实例

cargo build --release --locked --bin rustroad
target/release/rustroad init --workspace .work/demo \
  --base-rev rev0 --input fixtures/physical-small.json
target/release/rustroad place --workspace .work/demo --base-rev rev1
target/release/rustroad export-def --workspace .work/demo > .work/demo.def

构建前按 资源契约设置并发、内存和超时。目录必须是新的；init 不覆盖现有设计。
